决斗


## 目标

在群聊中实现猜拳决斗，A向B发起决斗，B可以选择接受或拒绝，若B接受，双方发送猜拳表情，由机器人判断胜负，胜者获得分数，败者失去分数。还可以查看分数排行榜。


## 触发条件

### 指令
()表示可选参数，|表示或
- /duel @成员
- /duel.accept @成员
- /duel.reject @成员
- /duel.rank (high|h (<最大显示条数>)) (low|l (<最大显示条数>)) # 两个参数的最大显示条数都默认为10条
### 自动检测
- 群成员发送猜拳表情
### 定时
- 定时删除决斗状态


## 行为与文案
- 触发/duel:
    - if @自己:
      - send("不能向自己发起决斗。" + 引用触发指令的消息)
    - elif @BOT_LIST中的机器人:
      - send("不能向BOT发起决斗。" + 引用触发指令的消息)
    - elif @GBPBot:
      - send("<GBPBot的群昵称> 已接受 <发送者的群昵称> 的决斗邀请。\n请双方发送猜拳表情。")
      - 保存决斗状态
      - send(猜拳表情)
    - elif 没有问题:
      - send("<发送者的群昵称> 向 <被@的成员的群昵称> 发起决斗。")
      - 保存决斗状态，等待另一方接受/拒绝
- 触发/duel.accept:
  - if @的成员之前未未向发送者发起决斗:
    - send("<@的成员的群昵称> 未向你发起决斗。" + 引用触发指令的消息)
  - elif 没有问题:
    - send("<发送者的群昵称> 已接受 <@的成员的群昵称> 的决斗邀请。\n请双方发送猜拳表情。")
    - 保存决斗状态，等待双方发送猜拳表情
- 触发/duel.reject:
  - if @的成员之前未向发送者发起决斗:
    - send("<@的成员的群昵称> 未向你发起决斗。" + 引用触发指令的消息)
  - elif 没有问题:
    - send("<发送者的群昵称> 已拒绝 <@的成员的群昵称> 的决斗邀请。")
    - 删除决斗状态
- 触发/duel.rank:
  - 读取本地文件中的分数数据
  - if 没有参数或同时存在high|h和low|l参数:
    - send(高分榜和低分榜) #高分榜仅显示分数为正数的成员，按分数从高到低排列；低分榜仅显示分数为负数的成员，按分数绝对值从高到低排列。高分榜和低分榜显示的条数各自不超过最大显示条数。排行榜的格式自行设计。
  - elif 只存在high|h参数:
    - send(高分榜)
  - elif 只存在low|l参数:
    - send(低分榜)
- 检测到群成员发送猜拳表情(包括GBPBot自己):
  - if 发送者处于等待发送猜拳表情的决斗状态(如果同时处于多场等待发送猜拳表情的决斗中，优先满足旧的决斗):
    - 更新决斗状态
    - if 该场决斗的猜拳表情均已就绪:
      - 判断胜负
      - if 未平局:
        - send("<胜者的群昵称> 在与 <负者的群昵称> 的决斗中获胜。<胜者的群昵称> 的分数+1，<负者的群昵称> 的分数-1。决斗结束。")
        - 更新本地文件中的分数数据
        - 删除决斗状态
      - elif 平局:
        - send("<决斗参与者A的群昵称> 与 <决斗参与者B的群昵称> 的决斗平局。双方分数不变。决斗结束。")
        - 删除决斗状态
- 某场决斗存在时间超过DUEL_DURATION:
  - send("<决斗参与者A的群昵称> 与 <决斗参与者B的群昵称> 的决斗超时结束。")
  - 删除决斗状态


## 实现要点

### 存储
- 决斗状态保存在内存中
- 分数数据保存在本地文件中，
### 配置项
- BOT_LIST = [<其它机器人QQ号>] # 机器人名单，所有群通用，供各插件共享
- DUEL_DURATION = <决斗超时时间> # 单位min # 默认10min
- 文档中直接出现的文案
