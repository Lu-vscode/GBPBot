道具

## 目标

- 在群聊中添加道具，群成员可以获取、查看、合成、交换和使用不同品质的道具，道具的功能尽可能**灵活多变**，以**机制**为主、数值为辅。
- 道具功能未来可能会成为本项目的核心玩法，需要慎重对待。
- 道具功能将来可能会与多种插件交互，目前主要与duel.py交互，需要深度重构duel.py，在决斗功能的各个环节中暴露出尽可能多的服务接口，为**灵活**的道具开发提供便利。
- 本文档主要服务道具功能主体的开发，只需要开发给出的几个示例道具，更多的道具留待未来开发。


## 道具的属性和信息
每个道具都应包含如下属性和信息：
1. 编号 每个道具具有唯一的三位数编号(000-999)，是区分道具的唯一标识，指令中用于指定道具的参数均应为编号，编号中的0在任何情况下都不能省略。编号一般会在道具开发时指定，如未指定则在开发时从100开始递增寻找可用编号并写入道具代码(000-099是为强大/特殊的道具保留的编号)，注册时不允许留空，保证每个道具的编号唯一确定
2. 名称 名称不一定唯一，在bot发送的消息中一般使用"<编号> <名称>"指代道具
3. 品质 道具品质分为黑色诅咒、灰色垃圾、白色普通、绿色精良、蓝色稀有、紫色史诗、金色传说，黑色诅咒均为负面效果，其余道具品质越高能力越强
4. 类型 道具分为以下几种类型
   1. 消耗型 最常见的类型，使用一次后消失
   2. 诅咒型 黑色诅咒品质对应的特殊类型，获得后自动使用并消失，产生负面效果
   3. Buff型 使用后会使某个成员在使用道具的群聊获得持续一段时间的某种状态，在状态持续期间，该成员的某些行为会有特殊效果，可以使用某些限定的指令。状态信息需保存在磁盘中，防止bot重启后丢失。
   4. 永久型 使用后使某个成员在道具使用的群聊永久获得某种特殊效果，相关记录也需保存在磁盘中
   5. 耐久型 使用一定次数后消失，使用过的耐久型道具不能合成/交换
   6. 可选型 使用时可以传入一些参数，产生不同的效果
   7. 复合型 上述几种类型的中的两种或多种的复合
   8. 特殊型 其它难以分类的类型 
5. 介绍 对道具的简要介绍
6. 功能 对道具功能的具体介绍
7. 使用条件 对使用道具需要满足的条件的介绍
8. 使用时机 对道具正确使用时机的介绍
9. 耐久 显示道具的可用次数，一般为"剩余耐久/总耐久"，部分特殊道具可能不同
10. 备注 关于道具的补充信息


## 获取道具
目前每人每次签到可以获得一个随机道具，抽取道具先抽取品质，再根据品质在对应的道具池中等概率抽取道具，获得不同品质道具的概率为:
- 黑色诅咒 0.055 
- 灰色垃圾 0.550
- 白色普通 0.250
- 绿色精良 0.100
- 蓝色稀有 0.030
- 紫色史诗 0.010
- 金色传说 0.005

不同品质道具的抽取概率可在env中配置，配置项的概率若为负则视为0，若总概率不等于1则归一化，若含有其它字符则报错并使用默认值

需要在签到记录中附加上获取的道具的编号

## 查看道具
使用/item.list查看自己拥有的道具，显示道具编号、名称、品质和数量，按品质由高到低排序

使用"/item.detail <道具编号>"查看自己拥有的某个道具的详细信息。发送的消息应包裹在合并转发中。


## 合成道具
使用/item.craft <道具编号1> <道具编号2>合成自己的道具。
用作合成材料的两个道具必须品质相同，可以是相同的道具，但用户拥有的道具数量必须足够。
合成后合成材料消失，获得一个随机品质的随机道具，新道具的品质概率为:
- 品质低一级 0.24
- 品质高一级 0.75
- 品质高两级 0.01

这个抽取概率也要可在env中配置，配置项的概率若为负则视为0，若总概率不等于1则归一化，若含有其它字符则报错并使用默认值

其中灰色垃圾道具降级后会获得黑色诅咒并自动使用，黑色诅咒显然没法合成，金色传说不能合成，紫色史诗抽中品质高两级后会获得两个金色传说


## 交换道具
使用"/item.exchange @成员 <自己拥有的某个道具的编号> <对方拥有的某个道具的编号>"发起道具交换。
不能与自己、BOT_LIST中的Bot、GBPBot交换道具。
交换的道具不需要品质相同，但一定是一换一。
一次未完成的交换的有效期为10min，保存在内存中，在有效期内不能向同一个人重复发起交换,交换过期后静默删除。
发送的消息中仅提供交换的道具的编号、名称信息，增加不确定性。

使用"/item.exchange.accept @成员"接受道具交换。

使用"/item.exchange.reject @成员"拒绝道具交换。


## 使用道具
使用"/item.use <道具编号> [其它参数]"使用自己拥有的道具。
可选型和含有选项的复合型道具可能需要加上其它参数。
成功使用道具后发送的消息、触发的效果由各个道具模块自行处理。

黑色诅咒道具在获得后自动使用前会发送一条消息显示道具的完整信息，随后转接给道具模块处理

## 实现要点

### 代码结构
以一个插件包的形式存在，包含一个主模块文件和多个道具模块文件，每个道具模块负责一个或多个道具
### 隔离
整个道具系统应该严格按照群聊隔离，并且仅限群聊使用
### 存储
各个群各个人拥有的道具、道具产生的状态信息需要保存在本地
需要记录在内存中的信息应当做好内存管理
### README
各个道具的信息不要暴露在README中，仅介绍道具功能的主体部分
## 文案
本功能的所有文案均可自行编写，均不需要在env中配置
